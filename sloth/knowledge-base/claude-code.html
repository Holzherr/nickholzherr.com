Claude Code

Claude Code with your subscription

If you have Claude Code installed and logged in, Sloth can write your meeting notes with it, so they use your Claude subscription instead of an API key. Claude Code runs from a folder you choose, which lets it use the context in that folder's CLAUDE.md and memory.

Set it up

  1. Install Claude Code and log in: run claude in Terminal once and follow the login steps.
  2. In Sloth, open Settings › Meetings › Meeting summaries and set Summary backend to Claude Code (your subscription).
  3. Check Status. It reads “Found Claude Code <version> at <path>” when Sloth finds it.
  4. Click Test. Sloth sends “Reply with OK” with no tools and shows “Worked: <model> in N.N s”, or the error.
  5. Pick a Model and a Run from folder.

Under the option Sloth shows: “Uses your Claude subscription and its usage limits. Transcripts are sent to Anthropic, as with an API key.”

How a run works

  1. Sloth builds one prompt from its summary instructions, your template, the meeting date, and the meeting material: title, transcript, your jottings and any earlier notes. Each piece of meeting material is wrapped and marked as untrusted data.
  2. Sloth starts Claude Code as a separate program in print mode (claude -p), in your chosen folder. Sloth passes a fixed list of options directly, without a shell, and sends the prompt on standard input. Meeting text never becomes part of a command.
  3. Claude Code writes the notes and reports each step back to Sloth as structured output.
  4. Sloth checks the result: it confirms no tool outside the allowed set was used, removes a stray code fence, redacts anything that looks like a secret, and adds any notices.
  5. Sloth saves the notes to the meeting and your Sloth folder.

Run from folder

Claude Code reads a folder's CLAUDE.md and memory when it starts there, alongside your personal Claude Code instructions. Running from a folder where you keep notes about your work, projects and colleagues gives Claude the background to spell names correctly, recognise projects and write sharper action items.

  • Click Choose… to pick the folder, or Reset to go back to the default (normally your home folder).
  • Sloth tells Claude to ignore workflow instructions in CLAUDE.md or memory about sessions, reading profile files, commits or pushes. They don't apply to writing notes.
  • Whatever Claude Code loads from that folder is sent to Anthropic with the prompt, as in any Claude Code session.

Let it look things up (read-only)

Off by default. With it off, Claude Code has no tools at all and answers from the prompt alone. With it on, it can use a short list of read-only tools from Claude's calendar, email, Notion and Slack connectors to add attendee and project context. It can never send, create, change or delete anything, and it can't read files on your Mac. Read How Sloth keeps Claude Code safe before turning this on.

What Sloth turns off

  • No saved session. Runs aren't saved as Claude Code sessions, so they don't show up in your Claude Code history.
  • No hooks. Your Claude Code hooks, which can run commands, are disabled for these runs.
  • No API key. Sloth doesn't pass API keys to Claude Code, so runs use your subscription login.
  • No retries. A failed run isn't repeated, so it doesn't eat into your usage twice. Sloth uses a stand-in provider instead.

When a run hits its limit, Sloth stops Claude Code and anything it started. Choosing Re-summarize again, or deleting the meeting, cancels a run in progress.

If it fails

Sloth writes the notes with Anthropic if you've set a Claude API key, otherwise with Apple Intelligence if it's available, and puts a line at the top of the notes, such as:

> Claude Code failed: Claude usage limit reached. Notes written with Anthropic.

If neither stand-in is available, the summary fails with Claude Code's error. For common errors, see Permissions and troubleshooting.
